# Configuration

The public reference is [`.env.example`](../.env.example); `config init` uses the
same template packaged as `app/config/default.env`. Local secrets and the CLI
session belong in the ignored `.maos/` directory. Generate `.maos/.env` before
Compose interpolation, then edit its real model configuration. Initialization
makes no database, account, run or provider call. See [first installation](self-hosting.md).

API/worker settings are environment variables parsed by `app.config.Settings`.
Direct Python development also reads a local `.env`; Compose explicitly forwards
its documented runtime variables. Passing `--env-file` to Compose supplies
interpolation values, and does not automatically forward every arbitrary key.

| Variable | Default / requirement | Meaning and validation |
| --- | --- | --- |
| `DATABASE_URL` | Required; generated by initialization | `postgresql+asyncpg://...` with explicit database; keep secret |
| `JWT_SECRET_KEY` | Required; generated | At least 32 characters, diverse generated secret; known placeholder patterns refused |
| `REDIS_URL` | `redis://localhost:6379/0` in code; Compose service `redis` | Notification dependency; loss degrades delivery while database replay remains authoritative |
| `APP_NAME` | `Multi-Agent OS` | Service identity |
| `APP_ENV` | `production` | `development`, `testing`, or `production` |
| `DEBUG` | `false` | Debug setting; production should keep false |
| `API_V1_PREFIX` | `/api/v1` | Other prefixes refused for this release |
| `BACKEND_CORS_ORIGINS` | Empty | Comma-separated explicit origins; no application frontend included |
| `LOG_LEVEL` | `INFO` | `DEBUG`, `INFO`, `WARNING`, `ERROR`, `CRITICAL` |
| `LOG_FORMAT` | `json` | `json` or `text` |
| `LOG_REDACTION_ENABLED` | `true` | Only true accepted |
| `METRICS_ENABLED` | `true` | Internal metrics collection |
| `METRICS_ROUTE_ENABLED` | `false` | Optional metrics route; protect any exposure |
| `METRICS_MAX_PATH_LABEL_LENGTH` | `120` | 20–500 characters |
| `JWT_ALGORITHM` | `HS256` | Only HS256 accepted |
| `ACCESS_TOKEN_EXPIRE_MINUTES` | `30` | 1–120; access tokens may remain usable until expiry after logout |
| `REFRESH_TOKEN_EXPIRE_DAYS` | `7` | 1–90; sessions rotate and are stored hashed/revocable |
| `LLM_PROVIDER` | `ollama` | `ollama`, `openai_compatible`, `groq`, `openrouter`, `gemini` |
| `LLM_MODEL` | Empty, must be selected for agent runs | Exact installed/available model, at most 200 characters; no default model download |
| `OLLAMA_BASE_URL` | `http://localhost:11434` in code; host gateway in template | Reachable HTTP(S) server base; `/api/chat` appended |
| `OPENAI_COMPATIBLE_BASE_URL` | Empty | Required for that provider; include `/v1` if needed; `/chat/completions` appended |
| `OPENAI_COMPATIBLE_API_KEY` | Empty | Optional secret for a self-hosted endpoint requiring bearer authentication |
| `GROQ_API_KEY` | Empty | Required secret for Groq |
| `OPENROUTER_API_KEY` | Empty | Required secret for OpenRouter |
| `GEMINI_API_KEY` | Empty | Required secret for Gemini |
| `LLM_TIMEOUT_SECONDS` | `60` | 1–300; total async HTTP deadline, bounded by agent timeout |
| `LLM_MAX_RETRIES` | `2` | 0–5 transient retries per request; every attempt consumes a persisted call |
| `LLM_MAX_OUTPUT_TOKENS` | `1024` | 1–32768; effective output limit is the smaller of profile and agent limits |
| `MAOS_EXTENSION_MODULES` | Empty | Comma-separated trusted installed modules, loaded identically by API and worker |
| `WORKER_HEARTBEAT_SECONDS` | `10` | 0.1–60; short database lease renewal interval |
| `WORKER_LEASE_SECONDS` | `60` | 1–600, and strictly greater than twice heartbeat interval |
| `WORKER_POLL_SECONDS` | `1` | 0.05–30; durable queued-job poll interval |
| `WORKER_CONCURRENCY` | `1` | Only one active run per worker supported |
| `MAX_WORKFLOW_NODES` | `32` | 1–32 |
| `MAX_PROVIDER_CALLS` | `16` | 1–128; persisted dispatch reservations include retries and recovery |
| `MAX_INPUT_BYTES` | `65536` | 1024–65536; external input JSON |
| `MAX_NODE_OUTPUT_BYTES` | `65536` | 1024–65536; validated persisted output per node |
| `MAX_RUN_BYTES` | `1048576` | 65536–1048576; input/context/node/final JSON |
| `MAX_EVENT_PAYLOAD_BYTES` | `4096` | 512–4096; event payload |
| `READINESS_TIMEOUT_SECONDS` | `2` | 0.1–30; dependency check deadline |

The runtime also honors the tighter limits in each installed workflow. Limits
are part of its persisted definition identity. Changing them can block old runs;
restore matching configuration/artifacts before resuming those runs.

Provider endpoints must be HTTP(S) without embedded credentials, query strings
or fragments. Credentials use their separate secret variables. Settings validation,
readiness and `doctor` do not send inference requests; explicit `provider check`
and workflow execution do. See [provider behavior and actual verification](providers.md).

Compose and CLI have these additional values, outside `Settings`:

| Variable | Reference value | Purpose |
| --- | --- | --- |
| `MAOS_API_PORT` | `8000` | Loopback API host port |
| `COMPOSE_PROJECT_NAME` | `multi-agent-os-core` | New namespace isolated from the graduation installation |
| `POSTGRES_USER` | `maos` | Explicit new database user |
| `POSTGRES_DB` | `maos` | Explicit new database |
| `POSTGRES_PASSWORD` | Generated | New database password; encoded URL generation uses the same generated value |
| `MAOS_UID`, `MAOS_GID` | Generated invoking host IDs | CLI profile user, so credential files are operator-owned |
| `MAOS_API_URL` | `http://api:8000` in Compose CLI | Public API base for ordinary CLI commands; local CLI defaults to loopback port 8000 |
| `MAOS_AUTH_FILE` | `/cli/auth.json` in Compose CLI | Shared persisted login, mode 0600; host directory mode 0700 |

No application setting enables fake inference, RAG/embedding/vector storage,
procurement stages, public registration or automatic seeding. Initialization does
not overwrite existing nonempty settings. Keep the configuration file mode 0600;
never paste `docker compose config` output with secrets. Validate Compose using
`config --quiet`.
